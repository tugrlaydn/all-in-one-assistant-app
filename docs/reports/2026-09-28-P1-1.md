# Session 2 — 2026-09-28 — P1: VaultKit core (all packages)

## In plain language
Persona can now read and write your files properly. This is the part you never see but depend on
every day. It understands every file type in the plan (notes, tasks with subtasks, habits, the weekly
habit log, the budget file), and it changes only the lines you actually changed. Your comments,
your spacing, keys it doesn't know (like Obsidian's `aliases:`) and the rest of the file stay exactly
as they were. That promise is checked automatically, on 200 generated files and on sample
files kept in the project.

It also refuses to overwrite a file that someone else edited in the meantime, such as Obsidian or
another Mac through iCloud. Instead it reports the conflict so the app can reload. It notices outside
edits within about half a second. The one-line quick-input language (`t Send invoice @fri !1 #work ~45m`,
`h swim 45 evening`) is now understood too, and a word it doesn't recognise always stays in your text.

There is still nothing new to click. The calendar window arrives in P2, and it will show your vault.
You stayed in the cloud this time, so a GitHub machine running macOS 26 built and tested every change.
The result is at the bottom of this report.

Choices P1 had to make that A15/A16 leave open. Each would become part of those decisions when you ratify:
- **File names:** the title is kept as written (spaces, case, Turkish letters). Only `/ \ : * ? " < > | # ^ [ ]`
  become `-`, because macOS, Windows or Obsidian can't use them in a name. An empty title becomes `Untitled`,
  and duplicates get `-2`, `-3`. A file is renamed only when its title changes, so a file you renamed
  yourself keeps its name.
- **`@fri` on a Friday means today** (use `@+7d` for next week).
- **Tokens only apply where they mean something.** `!1`, `~45m`, `>Parent` and `@date` inside a *note*
  stay part of the note's text. `#tag` in a habit log stays in its note. If you type the same kind of
  token twice (`@mon @tue`), the first wins and the second stays in the title.
- **`>Parent title` runs until the next token** (`t Draft PDF >Q4 invoicing @fri` → parent "Q4 invoicing").

## Technical detail
- **Commits (P1):** `97cee32` document layer → `34f7b32` models + golden files → `f8bde0b` Quick Input
  parser → `375c5a1` index → `862bb42` Vault service → `ded2f5b` watcher → `ffc2833` vaultctl →
  `d3d4a1c` fixes from the review pass.
- **Document layer (A07):** `MarkdownDocument` splits a file into BOM, front matter and body. It keeps every line with its
  exact terminator (split on UTF-8 bytes, because Swift treats `\r\n` as one Character). Invalid UTF-8 is refused
  rather than decoded lossily. `FrontMatter` reads the YAML subset the format needs: scalars with comments,
  quotes and escapes, flow and block lists, one-level maps and block scalars. A write replaces only the key's
  lines and keeps indentation, the comment and its column, list style and CRLF. Text scalars are quoted
  whenever YAML would read them as something else (numbers, dates, `true`, and `20:00`, which YAML 1.1
  reads as base-60).
- **Models:** each model is a view over its document. Setters are minimal edits: one front-matter line,
  one checkbox character (`ChecklistLine`), one inserted table row. Models remember
  `loadedDocument`, which the Vault uses for conflict refusal. `Day`/`ISOWeek` use Hinnant's civil-day
  algorithms (no `Calendar`/`TimeZone` drift) clamped to years 1–9999. `Timestamp` keeps its written offset,
  so a note created at 23:30 in Istanbul stays on that day.
- **Index (A06):** `VaultIndex` keeps derived maps (id, title, tag, link target, day) that are updated per
  entry. Links resolve by title, then the last path component, then id. Backlinks re-check resolution
  when titles collide. Fuzzy search is a subsequence match with bonuses for word starts, consecutive
  runs and prefixes, and ignores case and diacritics. The versioned cache is `.persona/index.json`.
- **Vault:** an `actor`. `load` reuses cache entries when the file's modification date and size match;
  it reports iCloud placeholders (and asks for a download) and non-UTF-8 files. `save` never writes an unchanged
  item. It compares and writes in *one* coordinated access, and only then renames if the title changed.
  Creates never overwrite, and `.X.md.icloud` stubs count as taken names. Paths cannot leave the vault.
  `rescan()`/`refresh(paths:)` feed the watcher and never write (§8.3: no write on a timer).
- **Quick Input:** `QuickInputParser.parse(line, today:, defaultKind:)` returns the fields and the token
  ranges for the chips. The grammar table has 61 rows, plus a property test that no word is ever lost.
- **Review pass (§8.5):** the `reviewer` subagent read the full P1 diff and reported 15 findings. All code
  findings are fixed with a regression test each (commit `d3d4a1c`). The most important were: typed `@+9999999d`
  or a huge `~…h` could crash (integer overflow); the compare and write were two separate
  coordinated steps; files were renamed on unrelated edits; the watcher wrote the cache on its
  tick; restarting the watcher killed the new stream; headings in code blocks were read as structure.
  The two non-code findings are in this report: the Tier A proposals above, and the undocumented
  file-name rules.
- **Tests:** 102 in VaultKit (Swift Testing), all against committed fixtures or private temp copies.
  Results: 102/102 on Swift 6.2 Linux (Docker). On macOS 26 CI, every P1 commit up to `ffc2833` passed
  (runs 4–8). The run for `d3d4a1c` ([run 9](https://github.com/tugrlaydn/all-in-one-assistant-app/actions/runs/36483984537)) was still running when this report was committed. The fuzz test also passed 6000 generated
  files across 30 seeds locally.
- **Acceptance (P1.md):** `swift test` green ✔; `make vault-dump` lists the fixture vault ✔ (verified
  with `swift run vaultctl` here and as a CI step); golden bytes identical ✔; no test touches a path
  outside the repo or the temp directory ✔ (a test also checks that a read-only open adds nothing to the fixture).
- **Risks and notes:** the conflict check sees edits made after the app read the file, but it
  doesn't merge; merging is P8. Links are not rewritten when a title changes: `[[Send invoice]]`
  stops resolving after a rename until P4/P5 add link updating. The cache lives inside the synced vault
  (FORMAT §4.1) and is written on load and after saves. Two Macs could produce an iCloud conflict copy of
  it, which is harmless because the cache is never truth. P8 measures this.
