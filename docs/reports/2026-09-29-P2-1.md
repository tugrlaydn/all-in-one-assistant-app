## Technical detail
- **Commits:** `8a156b1` ratification (decision files, indexes, grammar details, FORMAT §4.1 slug
  rules + change-log line) → `d00d18f` app code → `f047df4` app-test summary in the Makefile.
- **`VaultBookmarkStore`:** stores a `.withSecurityScope` bookmark in the app's defaults (the
  debug bundle id keeps its own copy, §8.6). Stale bookmarks are renewed. The bookmark closures can be
  injected for tests.
- **`FolderEvents`:** an FSEvents stream on the resolved vault path (`FileEvents | UseCFTypes | NoDefer`,
  0.2 s latency) on a private queue. It maps absolute paths to vault-relative ones and calls
  `VaultWatcher.nudge`.
- **`VaultSession`:** `@MainActor @Observable`. On launch it tries the debug `--vault` folder first, then
  the bookmark, then nothing. `open` does security-scoped access, `createSkeleton`, `load`, starts the
  watcher and FSEvents, and publishes the index. `close` undoes all of that. A test vault is never
  remembered. `chooseVault` uses `NSOpenPanel` and starts in iCloud Drive/Persona if it exists, else
  iCloud Drive, else home. It finds the real home via `getpwuid`, not the sandbox container.
- **Tests:** 5 new app tests. They run hosted in the sandboxed debug app, in temp folders, with a
  throwaway defaults suite: bookmark round trip, skeleton on open, an outside edit arriving via FSEvents,
  the next launch reopening the folder, test vaults never remembered, and a missing folder failing
  cleanly. macOS CI [run 13](https://github.com/tugrlaydn/all-in-one-assistant-app/actions/runs/36558461982):
  app 12/12, VaultKit 102/102, DesignKit 7/7, `make vault-dump` OK. `make test-app` now prints the
  result-bundle summary, so every CI log shows the counts.
- **Risk:** the security-scoped path (`.withSecurityScope` on a folder picked with the panel) can't be
  tested without a person clicking. The tests use plain bookmarks. It is standard API, but the first
  real launch is its first test.
